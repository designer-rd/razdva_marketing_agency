# Внедрение

Внедрение — ключевое отличие RazDva от консалтинга.

Задача внедрения: превратить выводы аудита и стратегию в работающие изменения в маркетинговой системе клиента.

## 1. Принцип внедрения

Мы не делаем “материалы ради материалов”.

Каждое внедрение должно отвечать:

1. Какую проблему решает?
2. Где в пути клиента используется?
3. Какой результат должен изменить?
4. Как будем проверять?

## 2. Что может входить во внедрение

- Упаковка оффера.
- Instagram-структура.
- Лендинг / мини-сайт / сайт.
- Страница доверия.
- Воронка WhatsApp.
- Скрипты обработки заявок.
- Креативы.
- AI-контент.
- Таблицы учета блогеров/каналов.
- Базовая аналитика.
- CRM/автоматизация.
- Презентации для партнерок.
- Контентная система.
- Координация подрядчиков.

## 3. Что делаем сами

Внутри RazDva:

- анализ;
- стратегия;
- структура;
- тексты;
- прототипы;
- дизайн-логика;
- лендинги/страницы;
- креативные гипотезы;
- AI-материалы;
- скрипты;
- таблицы;
- project management;
- контроль качества.

## 4. Что можно отдавать подрядчикам

Подрядчики могут подключаться на:

- сложную разработку;
- продакшн фото/видео;
- motion/3D;
- рекламные кабинеты при большом бюджете;
- SEO;
- юридическую проверку;
- интеграции CRM;
- типографию/офлайн-материалы.

RazDva остается владельцем логики и качества.

## 5. Как строится проект

### Этап 1. Kick-off

Цель:

- подтвердить объем;
- собрать материалы;
- назначить ответственных;
- согласовать сроки.

Выход:

- рабочий план;
- список доступов;
- канал коммуникации;
- дата первого результата.

### Этап 2. Структура

Создаем:

- карту страницы/воронки;
- структуру оффера;
- структуру контента;
- список блоков доверия;
- список CTA;
- требования к материалам.

Выход:

- согласованная структура.

### Этап 3. Производство

Делаем:

- тексты;
- дизайн;
- сборку;
- креативы;
- таблицы;
- скрипты;
- автоматизации.

Выход:

- черновик/первая версия.

### Этап 4. Согласование

Правило:

- одна итерация должна решать конкретные замечания;
- не менять стратегию на этапе мелких правок;
- фиксировать решения письменно.

Выход:

- утвержденная версия.

### Этап 5. Запуск

Проверить:

- ссылки;
- адаптив;
- формы;
- WhatsApp-сообщения;
- UTM/аналитику;
- кнопки;
- доступы;
- скорость загрузки;
- корректность текстов.

Выход:

- опубликованное внедрение.

### Этап 6. Тестирование

Смотреть:

- заявки;
- клики;
- ответы;
- конверсию;
- стоимость заявки;
- качество лидов;
- причины отказов.

Выход:

- отчет и следующие гипотезы.

## 6. Контроль качества

Перед передачей клиенту:

- [ ] Решение связано с проблемой из аудита.
- [ ] Есть понятный оффер.
- [ ] Есть CTA.
- [ ] Есть блоки доверия.
- [ ] Работает мобильная версия.
- [ ] Работают формы/WhatsApp.
- [ ] Нет внутренних заметок.
- [ ] Нет недоказанных обещаний.
- [ ] Клиент понимает, как использовать результат.

## 7. Ошибки внедрения

- Делать без стратегии.
- Делать красиво, но непонятно.
- Не проверять путь заявки.
- Не назначать ответственных.
- Не фиксировать сроки согласования.
- Не измерять результат.
- Брать на себя то, что должен дать клиент.

## 8. Передача из продаж в проект

Менеджер должен передать:

- карточку клиента;
- аудит;
- КП;
- согласованный объем;
- сроки;
- материалы;
- ограничения;
- обещания клиенту;
- следующий шаг.

Без этого проект нельзя запускать.
